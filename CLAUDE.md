# Grand Prix Automotive Service — CRM

Working notes for Claude Code. Read before making changes.

Vite + React + TypeScript, Supabase (Postgres + RLS + Edge Functions), deployed on Vercel.
Bilingual English / Arabic. Single shop, ~3 staff, Amman, Jordan.

---

## Invariants — do not break these

**The app never writes to the `reminders` table.**
Reminders are created and updated by database triggers from job line data. The app may
update `status` and call the RPCs `set_reminder_due`, `log_reminder_send`, and
`add_manual_reminder`. It must never `insert` into `reminders`, and must never write
`due_date` or `due_odometer` directly. If a feature seems to need it, the trigger is the
place to change.

**Totals are never stored.**
`jobs` has no total column. Money comes from `v_job_totals`, which sums
`part_price + labor_price + sub_price` across done lines. Never denormalise a total.

**`services.name_en` is NOT NULL; `name_ar` is nullable.**
The English name is the identifier — the picker searches it, migrations reference it.
An Arabic-only service cannot be saved; translate or type an English name.

**Costs are separated from prices by RLS.**
Technicians cannot select `job_items`. They read `v_job_items_nocost`. Any new view that
exposes cost must be granted deliberately, not by default.

## Conventions

**Strings.** Every user-facing string goes through `t('key')` in `src/lib/strings.ts`,
with a matching key in `strings.en.ts` and `strings.ar.ts`. `StringKey` is derived from
the English catalogue, so a missing Arabic key is a compile error. Empty Arabic values
fall back to English.

**Plurals** use `Intl.PluralRules` via `tn(count, base)`. Arabic needs `.zero`, `.two`,
`.few`, `.many` in addition to `.one` / `.other`. Never write `count === 1 ? … : …`.

**CSS is logical only.** `margin-inline-start`, `padding-inline-end`, `text-align: start`,
`inset-inline-start`. No `margin-left`, no `text-align: right`, no `float`. The stylesheet
was audited and is clean — keep it that way.

**Numbers stay Latin digits, dates stay ISO**, in both languages. Bare figures carry
`.num` (`direction: ltr; unicode-bidi: isolate`). Sentences containing figures carry
`.figures` (mono only) plus `dir="auto"` — forcing LTR on a sentence detaches the unit
from its number.

**Job lists order `start_date desc, job_no desc`** everywhere — Jobs, Dashboard, customer
detail. Never `created_at`.

## Bilingual data — three patterns, do not confuse them

**1. Bilingual pairs — translate.**
`customers.name_en/name_ar`, `services.name_en/name_ar`, `service_categories`,
`lookup_values.label_en/label_ar`. Both stored, UI picks one via `localised(en, ar)` with
fallback to the other. The `translate-service` Edge Function handles service names.

**2. Canonical Latin identifiers — normalise, never translate.**
`vehicles.make`, `vehicles.model`, `tire_brand`, `tire_size`, `fluid_brand`.
"Camry" is Camry worldwide; كامري is a spelling, not a translation. Storing both splits
the typeahead and breaks fleet counts. Arabic input should be normalised to the Latin
canonical form, not stored as a second value.

**3. Free prose — leave alone.**
Job descriptions, line notes, customer notes, mute reasons. Stored as typed, never
translated.

## Gotchas that have already cost time

**PostgREST array inserts need uniform keys.** Every row in the array must have the same
key set. `postgrest-js` builds `columns` from the union and writes NULL into any row
missing a key another row has. A conditional spread (`...(x ? { details } : {})`) caused
a NOT NULL violation this way. Always send the full shape.

**`create or replace view` cannot rename or reorder columns.** Drop then create. This has
been hit three times.

**Supabase's SQL editor pools connections, so temp tables do not survive between
statements.** A multi-statement script using `create temp table` fails with
`relation "_x" does not exist`. Use inline `VALUES` lists instead.

**`GENERATED ALWAYS` identity columns reject direct updates.** Renumbering `job_no`
required `alter column … set generated by default` first. It was left that way.

**Suspend triggers for bulk work.** `trg_create_reminder` fabricates reminders when
importing history; `trg_touch_job_line` stamps every job as edited. Disable both around
imports and line rebuilds, re-enable after.

## Workflow

After any migration: `npx supabase gen types typescript --project-id <id> > src/types/database.ts`

Commit after each completed task, not after several. A single commit spanning four
features cannot be bisected when the deploy breaks.

Verify query shapes against the live schema rather than trusting generated types — types
can lag, the API cannot. A 401 means the shape is valid and RLS refused; a 400 means the
column is wrong.
