# Database reference

Twenty-four migrations, applied in order against the live Supabase project. This is the
resulting shape — read this rather than the migrations.

---

## Core tables

**`service_categories`** — 17, ordered by `sort_order`. Bilingual.

**`services`** — 347. `name_en` NOT NULL, `name_ar` nullable, `code` nullable (null for
services created through the app). Carries `triggers_reminder`, `reminder_km`,
`reminder_months` as *hints* for prefilling job lines. Also `fluid_unit`
(`liters` | `grams` | null), `fluid_type_list`, `fluid_grade_list` — lookup list_keys
naming which dropdowns a job line should show — and `tracks_tires` boolean.

**`lookup_values`** — 20 lists keyed by `list_key`, bilingual labels. Includes
`payment_method`, `customer_source`, `vehicle_category`, `vehicle_make` (~48),
`oil_viscosity`, `oil_grade`, `trans_fluid`, `coolant_type`, `brake_fluid_dot`,
`refrigerant`, `parts_condition`. Also `reminder_km` / `reminder_months`, populated for
`oil_grade` only (mineral 5000/6, semi 7500/6, full 10000/12) and null on every other
list — a null pair is how the app knows a grade list carries no intervals.

**`staff`** — roles `admin` | `advisor` | `technician`, linked to `auth.users`.

**`customers`** — `name_en`, `name_ar`, `phone`, `whatsapp_opt_in`, `is_periodic`,
`source`, `notes`. Constraint `customer_identifiable`: at least one of name or phone.
One phone per customer — a separate `whatsapp_phone` column was added and dropped.

**`vehicles`** — `plate`, `vin`, `make`, `model`, `year`, `category`, `current_odometer`,
`km_per_day`. `make` is free text validated against a soft lookup list, deliberately not a
foreign key. `km_per_day` is optional: it turns an oil grade's distance interval into a
date, and without it only the grade's months apply.

**`jobs`** — `customer_id`, `vehicle_id` (both nullable), `job_no` (identity, GENERATED BY
DEFAULT after renumbering), `receipt_no`, `start_date`, `end_date`, `odometer`,
`payment_method`, `status`, `notes`, `updated_at`, `updated_by`. **No total column.**

**`job_items`** — `service_id`, `status`, `description`, `part_price`, `labor_price`,
`sub_price`, `subcontractor_id`, `warranty_months`, `next_due_odometer`, `next_due_date`,
`details` (JSONB, NOT NULL, default `{}`).

`details` keys in use: `fluid_type`, `fluid_grade`, `fluid_brand`, `fluid_qty`,
`tire_qty`, `tire_brand`, `tire_size`, `tire_dot`, `tire_condition`, `tire_rft`.

**`reminders`** — `vehicle_id`, `service_id`, `job_item_id`, `due_date`, `due_odometer`,
`status` (`pending` | `queued` | `sent` | `cancelled` | `superseded`), `sent_at`, `note`.
Unique index on `(vehicle_id, service_id)` where status is pending or queued.

**`reminder_mutes`** — `(customer_id, service_id)`; `service_id` null means mute
everything. Two partial unique indexes enforce one row per scope.

**`reminder_sends`** — one row per attempt. `channel`, `status`
(`sent` | `delivered` | `read` | `failed`), `provider_message_id`, `error_code`,
`error_detail`, `attempted_by`, `attempted_at`.

**Also:** `subcontractors`, `suppliers`, `parts_catalog` (empty), `service_parts`,
`job_item_parts`, `part_cost_history`, `settings`.

## Views

**`v_job_totals`** — the only source of job money.

**`v_job_items_nocost`** — technician-visible line view without cost columns.

**`v_reminders_live`** — every pending, non-muted reminder with a `bucket` column
(`due` | `upcoming`), plus `triggered_by`, `odometer_reached`, `date_reached`. Replaced
`v_reminders_due` and `v_reminders_upcoming`, which duplicated the mute rule.

**`v_reminders_dismissed`** — hand-cancelled reminders with no live replacement.

**`v_customer_contact_health`** — per customer: `no_phone`, `no_opt_in`, `failed_sends`,
`last_failure`, `last_success`, `last_attempt_failed`.

**`v_customer_mutes`**, **`v_service_usage`**, **`v_vehicle_models`**,
**`v_fleet_by_make`**, **`v_fluid_brands`** (keyed on `service_id`, not `code`),
**`v_fluid_usage`**, **`v_tire_brands`**, **`v_tire_sizes`**,
**`v_vehicle_tire_sizes`**, **`v_tire_fitments`** (includes computed `warranty_until`).

**Stats:** `v_revenue_by_category`, `v_revenue_by_service`, `v_revenue_by_month`,
`v_customer_activity`, `v_retention_by_month`, `v_lapsed_customers`. Revenue only —
margin is deliberately absent because `labor_cost` is estimated.

## Triggers

| Trigger | Table | Does |
|---|---|---|
| `trg_create_reminder` | `job_items` | On status `done`, calls `upsert_reminder_for_line` |
| `trg_sync_reminder` | `job_items` | Next-due changed → updates the reminder |
| `trg_cancel_reminder` | `job_items` | Line deleted → cancels its reminder |
| `trg_touch_job_line` | `job_items` | Any line change stamps the parent job as edited |
| `trg_sync_line_from_reminder` | `reminders` | Due changed → updates the job line |
| `trg_move_reminders` | `jobs` | Vehicle changed → cancels and recreates on the new vehicle |
| `trg_bump_odometer` | `jobs` | Applies the reading unless a later-dated job has one |
| `trg_touch_job` | `jobs` | Stamps `updated_at` / `updated_by` |
| `trg_apply_mute` | `reminder_mutes` | Muting cancels anything already pending |
| `trg_close_reminder` | `reminder_sends` | A successful send closes the reminder |

Both due-sync triggers guard on `pg_trigger_depth() > 1` to prevent recursion.

## Functions

**`upsert_reminder_for_line(line_id)`** — the single place reminders are created. Reads
the line, its service and its job; falls back to the service's interval when no next-due
was entered; supersedes any open reminder for that vehicle and service; inserts.

**`set_reminder_due(reminder_id, due_odometer, due_date)`** — replaces both values, does
not coalesce. Raises if both would be null.

**`log_reminder_send(reminder_id, status, channel, message_id, error_code, error_detail)`**

**`odometer_looks_wrong(vehicle_id, reading)`** — returns `'lower'`, `'jump'`, or null.
Warns, never blocks.

**`vehicle_odometer_without_job(vehicle_id, job_id)`** — what the reading would be
without that job. For display; nothing rolls back automatically.

**`apply_mute()`**, **`normalize_ar(text)`** (alef forms, ta-marbuta, diacritics, tatweel).

## Edge Functions

**`translate-service`** — POST `{ name, categoryId }` with the caller's auth header.
Detects script, pulls up to 12 same-category bilingual examples from `services` as
few-shot context, calls Claude Haiku 4.5, returns `{ translation, direction }`. Verifies
staff membership. Rejects a reply in the wrong script.

Secret: `ANTHROPIC_API_KEY`.
